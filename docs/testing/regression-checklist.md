# テスト実行チェックリスト（回帰確認用）

実装のたびに使い回す汎用チェックリスト。機能追加・改修時はここを更新し続けること。
（プロジェクト固有のUXレビュー成果物である `docs/UX_Review_and_Cross_Review.md` の
「9. テスト・検証チェックリスト」とは別物 — あちらは特定WPレビュー用のスコープ限定版）

## 使い方

1. 実装が一段落したら **A. 自動テスト** を必ず全部実行する。
2. 変更したファイル・機能に応じて **B. 対応表** から該当セクションを選び、手動確認する。
3. リリース前や大規模改修後は **C. データ品質原則チェック** と **D. フルリグレッション** まで通す。
4. 新しい機能領域やタブを追加したら、B に新セクションを追記し、末尾の更新履歴に日付を残す。
5. チェックリスト自体が古くなった（廃止された機能が残っている等）と気づいたら、その場で書き換える。

## B-1a. 連続入力フロー（基本記録タスク: 4輪空気圧・気温・ベストラップ・フィーリング）

想定文脈: 走行直後のピット／グローブ着用／直射日光／片手親指／電波が悪い。
この文脈に反する確認項目は無効とする。

### 聞く項目が絞られていること
- [ ] 起動すると質問は最大4つ（気温・タイヤ空気圧・ベストラップ・フィーリング）だけで、路面温度・湿度・気圧・天候・総周回数は聞かれない
- [ ] 環境データが自動取得できているとき、気温は聞かれない（質問は3つになる）
- [ ] 4種すべて入力済みのときは「未入力の項目を入力する」ボタンが表示されない
- [ ] 休止状態のカードはサマリーチップ表示で、見出しに「n/N 入力済み」バッジが出る。タップで展開・再タップで折りたたみ

### 操作寸法・可読性（グローブ・直射日光）
- [ ] テンキー・確定・中断・フィーリング5択・4輪選択が、いずれも60px以上ある
- [ ] 触る操作（4輪選択・テンキー・確定・中断）が画面下側にあり、片手親指で届く（390x844で y>=281）
- [ ] 薄いグレー文字（gray-400/500）が画面に出ていない。罫線がはっきり見える
- [ ] `src/lib/pitTheme.test.ts` が通る（全色ペアが対背景7:1以上）

### タイヤ空気圧
- [ ] 既定は**温間**。冷間/温間の切替が60px以上のボタン2つで出ている
- [ ] 冷間を選ぶと冷間欄へ、温間を選ぶと温間欄へ入る（取り違えない）
- [ ] 空いている方へ自動で切り替わったりしない（既定は常に温間）
- [ ] 3桁打って「FL を確定」で次の輪へ自動で進む。輪をタップすれば任意の輪へ移動できる
- [ ] 目標圧レンジ内は緑、レンジ外は橙で色分けされる
- [ ] 同一サーキット・同一タイヤセットの前回記録があるとき「前回と同じ N kPa を使う」が出る。押すまで値は入らない
- [ ] 50〜400kPa の範囲外は確定できない（打ち間違いを保存しない）

### ラップタイム
- [ ] 数字だけ打つと m:ss.mmm に整形される（`158423` → `1:58.423`）。記号キーボードへの切替が不要
- [ ] 秒が60以上になる打ち間違いは確定できない
- [ ] 未入力のまま次へ進める（null 保存になる）

### フィーリング
- [ ] 「どこで気になった?」で 低速/中速/高速 × 進入/中間/立ち上がり の9マスから選べる
- [ ] マスを選ぶと「どうだった?」で 強アンダー〜強オーバー の5択が出る
- [ ] 記録した箇所はマスに U/S++ 等が表示され、複数箇所を続けて記録できる
- [ ] 「気にならなかった」を選ぶと、9項目は null のまま総合バランスだけが残る（N で埋めない）
- [ ] スライダーが使われていない（DrivingTab の13項目も段ボタンになっている）
- [ ] 未評価のまま閉じれば null のまま保存される

### 手数
- [ ] 基本記録タスク（4輪＋気温＋ラップ＋フィーリング）が26タップ以内で完了する（前回引き継ぎ利用時は18タップ以内）

- [ ] コピー機能で本来引き継いではいけないデータ（ラップタイム・ロガー証憑・テレメトリ・共有状態）が引き継がれていない
